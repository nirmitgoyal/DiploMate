# Metrics pack

Run each file against prod with `heroku pg:psql < sql/metrics/activation.sql` (swap in `valid_recall.sql` or `d7_return.sql` as needed) to compute the ONE beta experiment from the event log. TD4 reads the two leading numbers together: green requires >= 40% valid recall AND D7 >= 30%, yellow is recall 20-40% or D7 15-30%, red is anything below that - and all three colors only mean something once there are >= 30 activated users (opened >= 1 topic); below that floor, treat the output as qualitative, not a verdict. Because activation is well under 100% of installs, TODOS item 4 recruits 45-50 installs to reliably clear the 30-activated floor and start TD4's four-week decision clock. Every window in this pack rides the event-carried `local_day` column (first 7 local_days from a user's first `topic_opened` for the recall window, `local_day >= first_day + 7` for D7) - `synced_at` is never used for windowing here and is reserved only for a separate skew sanity check on how late offline-first clients sync.
